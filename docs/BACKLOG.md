## Predictive Refactoring（预测性重构）

**提出**: 2026-06-03（来源：inbox 笔记）

**构想**: 利用 evolution 层的趋势分析能力，主动告诉用户哪里需要重构，并给出基于当前图谱的最优拆分方案。

**示例场景**:
> "根据最近 10 次提交，A 模块正在变得过于臃肿，建议拆分。基于当前调用图谱，最优拆分方案为：……（已生成方案）。"

**为什么是"杀手级"**:
- 传统静态分析只能告诉你"有问题"，无法告诉你"会变成什么问题"
- 加入 git 历史维度后，可以从"症状描述"升级为"轨迹预测"
- 配合调用图谱，可以从"建议拆分"升级为"给出最优拆分方案"

**依赖项**:
- EPIC-010 (Git Metrics Integration) — 已完成
- Evolution 层的趋势分析能力（`loomgraph_evolution_track` MCP composite 已有）
- 拆分方案生成需要图谱聚类算法（未实现）

**价值假设（待验证）**:
- AI agent 主动 + 历史轨迹 + 图谱推理三者组合是 LoomGraph 独有
- 与 codeindex 的 tech-debt 是延续关系（症状 → 趋势 → 处方）

**下一步**:
- 在 1-2 个真实重构案例上手工演练流程，验证"轨迹+图谱"是否真能给出比经验更好的拆分方案
- 验证通过 → 写 Epic；验证失败 → 砍掉，写一行 ADR 记录否定结论
