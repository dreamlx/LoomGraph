## 1. 产品愿景

### 1.1 一句话描述

> LoomGraph 是一款基于 H200 算力的私有化代码智能引擎，让开发者能够对千万行代码进行语义级别的理解、检索和依赖分析。

### 1.2 目标用户

| 用户角色 | 痛点 | 价值主张 |
|---------|------|----------|
| 企业架构师 | 大型遗留系统难以理解 | 全局依赖可视化，快速定位影响范围 |
| 高级开发者 | 跨模块调试耗时 | 语义检索 + 调用链追踪 |
| 技术负责人 | 技术债评估困难 | 代码健康度指标 + 热点分析 |
| 安全工程师 | 漏洞影响范围评估 | 敏感数据流追踪 |

### 1.3 核心差异化

1. **私有化部署**: 代码不出企业机房，100% 离线运行
2. **H200 原生优化**: 充分利用 141GB 显存，支持 8k 长上下文
3. **图谱+向量混合**: 不只是代码搜索，更是代码理解

## 2. 功能需求

### 2.1 核心功能 (Must Have)

#### F1: 代码索引引擎

| 需求 ID | 描述 | 验收标准 |
|---------|------|----------|
| F1.1 | 支持 Python/JavaScript/TypeScript/Go/Java 代码解析 | 能正确提取函数、类、方法定义 |
| F1.2 | AST-aware 代码切片 | 切片不破坏函数/类边界 |
| F1.3 | 增量索引 | 文件变更后 < 5s 完成重新索引 |
| F1.4 | 向量化存储 | 使用 Jina Code V2 生成 embedding |

#### F2: 图谱构建

| 需求 ID | 描述 | 验收标准 |
|---------|------|----------|
| F2.1 | 实体提取 | 识别函数、类、模块、变量等代码实体 |
| F2.2 | 关系映射 | 识别调用、继承、导入、依赖等关系 |
| F2.3 | 图谱存储 | 存储到 PostgreSQL，支持快速查询 |

#### F3: 混合检索

| 需求 ID | 描述 | 验收标准 |
|---------|------|----------|
| F3.1 | 关键词搜索 | 精准匹配变量名、函数名 |
| F3.2 | 语义搜索 | 自然语言查询代码功能 |
| F3.3 | 图谱查询 | 查询调用链、依赖关系 |
| F3.4 | 混合排序 | 三路结果智能融合排序 |

#### F4: MCP 服务接口

| 需求 ID | 描述 | 验收标准 |
|---------|------|----------|
| F4.1 | 实现 MCP 协议 | 兼容 Claude Desktop / Cursor |
| F4.2 | 代码检索工具 | 提供 `search_code` tool |
| F4.3 | 依赖分析工具 | 提供 `analyze_dependencies` tool |

### 2.2 扩展功能 (Should Have)

| 需求 ID | 描述 | 优先级 |
|---------|------|--------|
| F5.1 | 文件监听自动更新 | P1 |
| F5.2 | 多仓库支持 | P2 |
| F5.3 | 代码健康度指标 | P2 |
| F5.4 | Web UI 可视化 | P3 |

### 2.3 暂缓功能 (Won't Have - v1)

- 企业级 RBAC 权限管理
- 多租户隔离
- 实时协作编辑集成

## 3. 非功能需求

### 3.1 性能需求

| 指标 | 目标值 | 测量方法 |
|------|--------|----------|
| 索引吞吐量 | ≥ 10,000 files/min | 对 1M 行代码库计时 |
| 向量检索 P99 | < 50ms | Top-100 查询 |
| 图谱查询 P99 | < 200ms | 2-hop 遍历 |
| 冷启动时间 | < 30s | 服务就绪时间 |

### 3.2 可扩展性

| 指标 | 目标值 |
|------|--------|
| 代码库规模 | ≥ 10M 行（单索引） |
| 向量数量 | ≥ 1M vectors |
| 实体数量 | ≥ 500K entities |

### 3.3 可靠性

| 指标 | 目标值 |
|------|--------|
| 服务可用性 | 99.9% (本地部署) |
| 数据一致性 | 最终一致（< 5s 延迟） |
| 故障恢复 | 自动重连 + 重试 |

### 3.4 安全性

- 所有数据本地存储，不外传
- 支持 TLS 加密通信
- 敏感配置（API keys）环境变量注入

## 5. 用户故事 (User Stories)

### Epic 1: 代码索引引擎

```
作为一名开发者
我想要快速索引我的代码仓库
以便后续进行语义检索和依赖分析
```

**验收标准**:
- [ ] 支持 `loomgraph index --path <repo>` 命令
- [ ] 索引进度可见（进度条/日志）
- [ ] 索引完成后输出统计信息

### Epic 2: 代码检索

```
作为一名开发者
我想要用自然语言搜索代码
以便快速找到实现特定功能的代码片段
```

**验收标准**:
- [ ] 支持 `loomgraph search "处理用户登录的函数"` 命令
- [ ] 返回相关代码片段 + 文件路径 + 行号
- [ ] 结果按相关性排序

### Epic 3: MCP 集成

```
作为一名使用 Claude/Cursor 的开发者
我想要在 IDE 中直接查询代码
以便在编码过程中获得上下文帮助
```

**验收标准**:
- [ ] MCP 服务可在 Claude Desktop 中配置
- [ ] 提供 `search_code` 和 `get_dependencies` 工具
- [ ] 查询响应时间 < 2s

## 7. 开放问题 (待讨论)

> 以下问题需要在开发前确认：

### Q1: 存储架构

- **选项 A**: PostgreSQL 统一存储（向量 + 图 + 元数据）
- **选项 B**: PostgreSQL(元数据) + pgvector(向量) + 独立图数据库

**倾向**: 选项 A（简化运维）

### Q2: LightRAG 定制程度

- **选项 A**: 直接使用 LightRAG，仅替换 embedding/llm 函数
- **选项 B**: Fork LightRAG，深度定制图谱存储到 PostgreSQL

**倾向**: 先 A，后 B（如有需要）

### Q3: 多语言支持优先级

- **阶段 1**: Python + JavaScript/TypeScript
- **阶段 2**: Go + Java
- **阶段 3**: C/C++ + Rust

**待确认**: 是否符合用户实际需求？

### Q4: Jina Code V2 部署方式

- **选项 A**: Text-Embeddings-Inference (TEI)
- **选项 B**: 直接 transformers + 自定义服务
- **选项 C**: vLLM embedding 模式

**待确认**: 哪种方式在 H200 上吞吐量最高？
